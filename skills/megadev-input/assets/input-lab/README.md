# Input Lab

A standalone Megadev disc shows live 3/6-button pads, mouse packets, stable adapter sockets and joined players. A separate scripted mode demonstrates mixed Team Player packets without pretending hardware is attached. The controls and layout are illustrative diagnostic choices.

## Build

Generate a new copy with the installed skill's `scripts/create_project.py`, then run from that directory:

```sh
docker pull ewrogers/megadev:latest
docker run --rm --mount "type=bind,source=$(pwd),target=/workspace" ewrogers/megadev:latest build
docker run --rm --mount "type=bind,source=$(pwd),target=/workspace" ewrogers/megadev:latest cue input_lab.iso
```

Use Linux containers. PowerShell mounts use `source=$($PWD.Path)`; Linux users can add `--user "$(id -u):$(id -g)"`. Load with `ares --system "Mega CD" /path/to/input_lab.cue`, using your own configured BIOS. Keep that image immutable while rebuilding elsewhere.

## Controls and display

| Pad control | Inspector action |
| --- | --- |
| A | Switch the button/guide view. |
| B | Select a physical socket. |
| C | Toggle LIVE DEVICES / SCRIPTED DEMO. |
| Start | Join a logical player on a fresh press. |
| D-pad / X/Y/Z/Mode | Observe button state and menu-repeat behavior. |

The usual keyboard mapping is J/K/L/Enter and arrows/WASD. Those are emulator mappings, not part of the game API. Ares's Mega CD mappings are separate from Mega Drive. Select the correct emulated device in its Mega CD menu, then assign that device's controls in Input settings. Port 1 can stay a usable pad while port 2 tests another device.

Each card names a physical endpoint (1A–1D or 2A–2D), type and optional logical player number. H is held, + pressed, - released and R direction repeat; masks are hexadecimal. The selected socket's named buttons turn green while held. A mouse also shows per-packet dx/dy and a colored cursor in the bottom field. Its Y increases down the screen. No input is present in empty subslots.

The SUB counter shows the preserved Sub interrupt heartbeat; it is not CPU load or FPS. Rendering updates a bounded list of changed cells, so the UI does not clear/redraw the entire screen every frame. Edges are per-frame observations, not a historical event log.

## Modes and checks

AUTO reads supported direct devices and Team Players. A direct device occupies subslot A. Team Player needs its MULTI switch position. Ares v148 offers pads and mouse, but **no multitap device option**.

For an EA 4 Way Play or compatible EXTRA-mode adapter, build a fresh copy with `EA_MODE=1`. It reserves both physical ports and displays four pad sockets under port 1. It is not interchangeable with Team Player mode and does not support mice. That path has scripted/compiled tests and still needs real adapter qualification.

`TOUR=1` starts the clearly labeled scripted demonstration. Six virtual users join from two mixed Team Player packets; after the checks it displays AUTO PASS and **keeps the demonstration running**. The script uses the same decoders/state model. It does not prove that a physical adapter, mouse or controller was read.

US/NTSC is default. Use `REGION=EU VIDEO=PAL` or `REGION=JP VIDEO=NTSC` with a matching BIOS. Clean or use a new copy between configurations. The repeat clock accounts for 50/60 Hz, but meeting actual frame deadlines still needs measurement.

## Implementation boundaries

`input.c` handles packet decoding and snapshots. `protocol.c` is the project-owned physical protocol; `platform.c` uses Megadev I/O/Z80 constants and bounded bus acquisition. No SGDK input API is used. Mouse/Team Player/EA readers are supplied by this Lab, not upstream Megadev driver functions.

The ordinary BIOS frame handler also polls input. This Lab installs one custom interrupt after boot, pulses Sub INT2, commits the prepared UI and returns through RTE. BIOS joypad mirrors are no longer its live interface. Do not transplant that handler over another game's renderer/audio/raster/communication service without integrating those responsibilities.

Input batches preserve the caller interrupt mask and a previously granted Z80 bus. Serial waits cap both individual acknowledgment reads and total packet work, restore idle lines and clear failed samples. These bounds are not real-device timing qualification. There is no audio in this diagnostic example.

The original opaque font is generated by `tools/make_font.py` using only Python's standard library; no generated art service is required. Upstream startup notices remain in `LICENSE.megadev`. See the installed skill references for API/source evidence, tests and outstanding physical-hardware checks.
