# Glasshouse After Hours

An original, small exploration game for the cross-skill validation milestone.
You are an evening gardener restoring rainwater to a dormant moonflower. The
conservatory and rainworks share resident character/UI art, while their background
patterns and maps load from disc. The setting, palette, music, puzzle and controls
are illustrative; they are not recommendations for other games.

## Build and play

From the repository root, create a new disposable project:

```sh
python validation/create_project.py build/my-glasshouse
cd build/my-glasshouse
docker run --rm --cpus=2 --platform linux/arm64 --mount "type=bind,source=$PWD,target=/workspace" ewrogers/megadev:latest build
```

Choose `linux/amd64` for x64. PowerShell can use `${PWD}` for the source path.
Generated projects contain every build/runtime/host-check dependency; the
repository test harness is not needed to play. Use `REGION=EU VIDEO=PAL` or
`REGION=JP VIDEO=NTSC` in a fresh build for another region. Open `glasshouse.cue`
in ares with your matching configured BIOS; CLI launch must specify
`--system 'Mega CD'`. No BIOS is provided.

| Control | Action |
| --- | --- |
| D-pad | Walk, choose a menu option or valve route |
| A | Talk, reveal/advance text, confirm, use a nearby door |
| B | Field notes; close dialogue or return from a menu |
| Start | Pause/resume; title selection |

Begin, then speak to Rowan by the upper-left window. Use the door on the right
of the conservatory. In Rainworks, prime the pump on the left, then set the valve
on the right to **Garden**. Return through the left door and tend the moonflower
on the right side of the conservatory. Field notes track the three requirements. A bobbing down-arrow and page count
show when dialogue has more pages; A first reveals the current page, then advances.

Pause → Save Notebook saves only this game's named records. Return to Title →
Continue restores room, position and progress. Wait for NOTEBOOK SAVED before
leaving. Saving during a live load is refused with a retry notice; it never takes
the loader's mailbox. Unformatted/unavailable backup RAM leaves the game playable.
This game neither formats media nor writes saves in its automatic tour.

## What is being validated

- Existing scene leases, cancellation/draining, CD loading and resident shared art.
- A single CD/audio owner; music intent survives data reads, PCM cues stay resident.
- Existing nine-slice UI/page publication and bounded text layout, with a new game
  controller. Text reveal waits for the actual page acknowledgement.
- Explicit save schema validation, copied snapshots, CRC recovery and generation-
  checked Continue intent. The wire fields are adapted to this game's room/X and
  packed Y/progress, not treated as the old Lab's level/coin design.
- Original-M68000 execution, equal logical PAL/NTSC time, bounded interrupt uploads
  and an incremental generated-font/header rebuild regression.

Original art is drawn at native resolution by `tools/make_art.py`, without image
resizing. Two original CD arrangements and finite PCM cues are generated by
`tools/make_audio.py`. This is a functional integration fixture, not a genre skill.

With Python and a host C17 compiler, run `python tools/check_garden.py`. It checks
progression/choices, movement, pause, semantic save rejection and corrupt-record
recovery at O0/O3, with UBSan outside Windows. Repository `tests/integration.py`
adds real compiled M68000 execution and both-container regional matrices.

`TOUR=1` exercises scene travel, preload cancellation and missing-file recovery.
It never writes BRAM; persistence tests use a modeled BIOS with private records.
The tour is a correctness check, not a benchmark.

Incremental builds track local headers and assembly `incbin` resources explicitly.
Changing region/compiler flags still requires a clean or fresh build. Emulator
success and captured MMIO writes do not qualify physical drive/IRQ/audio timing.
See the repository's cross-skill validation notes for ownership and limitations.
